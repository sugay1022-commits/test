# 環境監査（読み取り専用）

Claude Code環境の設定資産を棚卸しし、改善提案レポートを作成する。**承認が出るまでファイルの作成・編集・削除は行わない。**

## 手順

1. **走査**（読み取り専用ツールのみ使用）
   - `~/.claude/`：CLAUDE.md / skills/ / agents/ / rules/ / commands/ / output-styles/ / settings.json
   - 各リポジトリ直下：CLAUDE.md / README / .claude/（settings.json, hooks, agents, skills）/ .mcp.json / .github/
   - リモートコンテナで実行している場合は「ローカルPCの資産は見えない」ことをレポート冒頭に明記する
2. **分類**：発見物を「プラットフォーム管理（触らない）／ユーザー資産／アプリのデータ」に分ける
3. **問題検出**（6観点）
   - 重複ルール（統合候補）／新旧の矛盾／使われていない死んだ記述
   - 粒度のバラつき（抽象的すぎ・細かすぎ）
   - Skill description の曖昧さ（意図したタイミングで発火しないリスク）
   - 常時読み込みのトークン浪費（逆に、CLAUDE.md不在による毎回の再探索コストも問題として扱う）
4. **レポート作成**
   - 全体マップ（ツリー形式）→ 問題一覧（影響度×工数マトリクス）→ 改善アクション（優先度 High/Mid/Low）→ 理想形の構成図
   - 振り分けの原則：常時参照→CLAUDE.md／手順→Skill／強制ルール→Hook・permissions／分離したい処理→Subagent／人間向け→README
5. **提示して停止**：レポートを提示し、ユーザーの承認（GO）があるまで実装しない
